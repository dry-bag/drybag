`stayfixed attach` and `stayfixed detach` no longer refuse an attach ledger that names files, settings keys or directories `attach` never wrote, and a ledger that is not valid JSON now records nothing: `attach` carries on and writes a new one, `detach` fails and removes nothing. The ledger sits in the git common directory, which a branch cannot write, so `attach` is its only author; `detach` instead removes a `.codex/rules/` copy only from a single file under that directory, a settings key only if it is `autoMemoryDirectory`, and a directory only from the closed list `attach` creates, and skips anything else the ledger names.
